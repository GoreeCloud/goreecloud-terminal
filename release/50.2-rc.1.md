# GoreeCloud Terminal 50.2-rc.1

Release Lifecycle: **Release Candidate**

GoreeCloud Terminal 50.2-rc.1 is the first controlled release-candidate line of the GoreeCloud-maintained Ptyxis fork. It is intended for final acceptance and must not be represented as Stable or production-approved until the remaining supported-workstation and production-readiness gates are complete.

## Material changes

- Establishes the canonical GoreeCloud Terminal product identity while retaining compatibility-sensitive `ptyxis` and `ptyxis-agent` runtime/helper names.
- Adds official GoreeCloud artwork and Glaze UI application chrome while preserving VTE ownership of terminal rendering and palette behavior.
- Adds typed Wardveil Security context presentation for verified Remote, Container, and Elevated session states.
- Adds GoreeCloud terminal context-menu workflows while preserving normal shell and `sudo` authorization boundaries.
- Adds the canonical `goreecloud-terminal` launcher and GoreeCloud application/GSettings identities.
- Adds staged runtime-identity validation and fail-closed optional migration/rollback tooling for upstream Ptyxis settings.
- Adds standard OpenSSH launch workflows plus optional non-secret host-profile/workspace organization. OpenSSH remains authoritative for hostname resolution, authentication, keys, agents, host-key verification, ports, proxies, forwarding, and connection policy.
- Adds an isolated development Flatpak and a production-identity RC Flatpak using GNOME Platform/SDK 50 with pinned declared support dependencies and disabled implicit Meson dependency downloads.
- Adds exact-artifact lifecycle validation, data-preserving local-bundle replacement, rollback logic, machine-readable release lifecycle state, a minimized Privacy Shield adapter, and a read-only local status API.
- Targets Glaze UI 1.4.0 Stable at the source-contract level.

## Packaging

Production RC application ID: `com.goreecloud.Terminal`

Development application ID: `com.goreecloud.Terminal.Devel`

Canonical launcher: `goreecloud-terminal`

The release uses the GNOME 50 Flatpak runtime/SDK. Exact published artifact checksums and immutable package evidence must be recorded from the final accepted release build; a rebuild from the same source is not automatically treated as the same artifact.

## Upgrade and migration

Installing GoreeCloud Terminal does not automatically migrate existing upstream Ptyxis settings.

The optional settings migration tooling is dry-run by default, reads `/org/gnome/Ptyxis/` as its source, refuses to overwrite a non-empty GoreeCloud target, snapshots state privately, verifies exact migration results, and supports rollback to the recorded pre-migration target.

Local Flatpak bundle replacement is validated using data-preserving application removal without `--delete-data`, followed by installation of the exact verified bundle. This is not represented as repository-backed `flatpak update` acceptance.

## Compatibility

The release preserves standard Bash/Zsh, PTY, OpenSSH, `sudo`, tmux, Git, Docker, systemd, and inherited Ptyxis compatibility boundaries. GoreeCloud profile metadata does not replace `~/.ssh/config` and contains no private keys, passwords, tokens, or transport policy.

## Known limitations and Stable blockers

50.2-rc.1 remains Release Candidate until the applicable final acceptance is complete, including:

- supported-workstation graphical runtime acceptance;
- terminal rendering, PTY, shell startup, Unicode/font, tab/session, keyboard-shortcut, selection, and clipboard acceptance;
- detector-driven Wardveil runtime transitions and mixed-tab behavior;
- Glaze UI light/dark, accessibility, palette, transparency, focus, and reduced-motion acceptance on the supported workstation;
- real OpenSSH controlled-host connection, host-key verification, authentication, failure, and disconnect behavior;
- settings persistence and controlled migration/rollback in a real user environment;
- final Flatpak permission-minimization review;
- production package install/removal/coexistence acceptance;
- a second distinct accepted package and repository-backed cross-version update/rollback acceptance;
- post-rollback data compatibility and recovery acceptance.

## Security and privacy

No telemetry, analytics, cloud synchronization, terminal-content collection, command collection, credential collection, or remote logging is introduced by this release. The local status API is read-only and does not expose terminal contents, session contents, profile contents, host inventory, credentials, or private SSH configuration.

## Release boundary

A successful source merge proves source integration. A published tag/release proves controlled release publication. Neither state alone proves deployment, production acceptance, or Stable maturity. GoreeCloud Terminal must remain labeled **Release Candidate** until the authoritative lifecycle record is explicitly promoted on completed evidence.
